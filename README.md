# ai-legacy-rewrite

AI 协同改造旧项目（重构或重写）的分阶段操作规程。先评估修 / 重构 / 重写哪种最小足够，再把旧代码库提炼成功能契约与交接包，在与旧仓库物理隔离的新目录、新会话里重写，用交叉审计、模块级子 Agent 复核、影子彩排和兼容探针验证，最后按选定切换策略上线。

方法来自卡兹克《开源 100 万月活级产品 AIHOT》的 12 步重写实践，经对抗式审查后修订为 v0.2.0。

## 仓库结构

```
SKILL.md                              Agent Skill 主文件（frontmatter + 流程）
references/
  prompts.md                          P0–P8 提示词模板
  checklists.md                       C0–C5 检查清单
  architecture-principles.md          候选架构原则（按项目取舍）
assets/
  rewrite-tracker.md                  进度、差异清单、探针跟踪模板
evals/
  evals.json                          边界用例（尚未运行）
```

## 何时使用

- 评估「修还是重写」
- 把旧代码蒸馏成需求文档、功能规格或交接包
- 规划多模型 / 多 Agent 协同重写
- 设计新旧一致性审计、影子彩排或切换回滚

不适用于单个函数/文件的小重构、纯代码风格整理、与旧系统无关的新项目。

## 核心约束

1. **重写阶段与旧代码物理隔离**：新目录 + 新会话 + 旧仓库不在可访问路径。规格不清回流给 Spec Owner，重写者自己不查旧实现。
2. **入口先定模式**：评估 / 方案 / 提炼 / 实施 / 切换 / 审阅，以及重构（行为不变）还是重写（允许已批准差异）。
3. **凭据不得明文进入规格、交接包或仓库**。
4. **彩排先列副作用清单**；有对外写操作时走完整版隔离与数据回退演练。

## 安装到 Agent

把本目录复制到当前 Agent 的 skills 目录，并在 Agent 级 `skills.jsonc` 登记 `name` / `description` / `installPath`。仅放目录、不登记注册表时，面板可能不显示名称和描述。
