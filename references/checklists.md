# 检查清单（C0–C5）

每个阶段结束时逐项核对。每项状态只能是：通过 / 未通过（写原因和下一步）/ 不适用（写理由）。
"不适用"用于该项对本项目确实无意义（例如没有数据库就没有空库迁移），不能用来掩盖缺证据或未执行。
"风险可接受"必须写记录人和理由，且它不等于通过。

## C0 评估结论（阶段 0）
- [ ] 改造方式（局部修复 / 重构 / 渐进替换 / 重写）已选定，有对比依据
- [ ] 任务模式（评估 / 方案 / 提炼 / 实施 / 切换 / 审阅）和改造类型（重构 / 重写）已确认
- [ ] 风险分级已回答：有无对外写操作、能否停写
- [ ] 若选重写：有可运行的线上/旧版本作验收基准；数据可导出；对外契约可枚举
- [ ] 若结论是"不重写"：已输出修复建议并结束，未进入阶段 1

## C1 规格质量（阶段 1）
- [ ] 能力清单与至少两个独立来源交叉核对过，每项有来源证据
- [ ] 每项能力有验收场景；每个契约有编号；每个场景有比较规则
- [ ] 数据归属清楚：同一份数据只有一个写入方
- [ ] 踩坑细节可追溯到旧代码位置
- [ ] 已批准差异清单存在；改变业务含义的项已由用户/Spec Owner 批准，未批准的不进最终规格
- [ ] 两份独立规格已交叉对照，补漏清单已合并
- [ ] 规格、交接包、提示词中**没有任何明文凭据**

## C2 重写隔离 + PR 门禁（阶段 2）
隔离（阶段开始核对一次，记入 tracker）：
- [ ] 重写使用新会话，未继承提炼/审计阶段上下文
- [ ] 工作根目录是 `{{new_dir}}`，旧仓库不在其中、无软链或挂载（记录实际路径）
- [ ] 规格疑问全部经 open_questions 回流，没有重写者直接查阅旧代码的记录
门禁（每个 PR，按项目取舍，不适用的写理由）：
- [ ] 类型检查
- [ ] 构建
- [ ] 空库迁移（有数据库时）
- [ ] 启动冒烟
- [ ] 兼容探针（对照契约编号）
- [ ] 不变量测试

## C3 审计闭环（阶段 3）
- [ ] 审计报告的每条结论已分类：缺陷 / 预期变化 / 疑似遗漏 / 待证实
- [ ] 阻断和重要缺陷已修复并回归；"不修"项有记录人、理由、影响
- [ ] 预期变化全部能对应到已批准差异清单
- [ ] 待证实项已证实或已按"未执行/证据不足"记录，不得直接关闭
- [ ] 模块复核在干净上下文执行；本轮无新增问题时已停止，未继续扩范围
- [ ] Bug/安全审查结果已处理

## C4 彩排与切换（阶段 4）
轻量版（无对外写操作、可停写）：
- [ ] 副作用清单已列，结论为"无"并有依据
- [ ] 至少一次彩排，探针按比较规则判断，结果按 PASS/FAIL/未执行/不适用统计
- [ ] 切换策略已选（通常为停写窗口），旧系统可切回
- [ ] 切换窗口、影响范围已与用户确认
完整版（有对外写操作或不能停写，在轻量版基础上追加）：
- [ ] 每项副作用在彩排中有明确隔离方式（桩/沙箱/禁用/只读凭据），彩排未触发真实外部写入
- [ ] 彩排数据范围经用户授权，优先脱敏快照或样本
- [ ] 迁移策略已定：一致性点、转换规则、完整性校验、队列去重、切换后校验
- [ ] 回退方案覆盖"切换后新写入数据如何保留"；无法无损回退时已明示并有前向修复方案
- [ ] 迁移和回退各实际演练一次，有记录
- [ ] 旧接口过渡期和下线日期已写明
通用：
- [ ] 记录了被测代码版本、规格版本、数据快照版本
- [ ] 切换前后各有一份性能基线
- [ ] 切换执行前取得用户明确确认

## C5 持续运营（阶段 5）
- [ ] 告警分级，重复告警合并
- [ ] 前后对比指标注明统计口径
- [ ] 新需求先更新规格和差异清单，再改代码

## 最容易踩的坑
1. 重写没有物理隔离（原仓库里开新会话、旧仓库仍可访问）→ 一次 grep 就把旧实现读进上下文
2. 把混乱的需求原样搬过去 → 长成新的屎山
3. 没有已批准差异清单 → 审计把改对的东西当回归改回去
4. 规格和测试同源 → 漏了的功能测试也一起漏，探针全过仍不完整
5. 彩排没隔离副作用 → 新旧两套同时发通知、扣费、写第三方
6. 只演练了代码回滚 → 切回后切换期间的新数据丢失
7. 写和审用同一段上下文 → 盲区重复出现
8. 明文凭据进了交接包、提示词或仓库
